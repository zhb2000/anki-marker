# 句子面板：单词排版与单词级过渡动画

本文档讲设计理念、抽象方式和实现思路，不逐行解释代码。相关文件都在 `src/components/`：

| 文件 | 职责 |
|---|---|
| `sentenceBreak.ts` | 断行：整段最优，决定每行放哪些原子、每行的空格多宽 |
| `sentenceLayout.ts` | 排版：把词元变成原子，调用断行器，输出每个词的坐标；上文、正文、下文纵向堆叠 |
| `sentenceChange.ts` | 判断两次文本变化的类型（并入、撤销、替换），并让词元 key 跨变化保持稳定 |
| `sentenceFlow.ts` | 并入 / 撤销的动画规划：每个词怎么走、什么时候走（纯函数，无 DOM） |
| `SentencePanel.vue` | 把以上接到 DOM：量字宽、驱动逐帧动画、让选区底色跟随 |

## 1. 为什么自己排版

动画想做的是“同一个词从旧位置连续地走到新位置”。浏览器流式排版只给出“重排前”和“重排后”两个状态，中间没有可以插值的东西，只能整块平移或用遮罩假装。自己排版后，每个词在任何一次排版里都有明确的 `(x, y, width, height)`，位置由我们算，浏览器只负责画字。这是后面所有动画的前提。

两段式思路借自 Pretext：测量一次（有缓存），之后排版只是对缓存宽度做算术。区别是我们用隐藏的 DOM 节点量宽，而不是 canvas。canvas 的字体解析和 CSS 不是同一套，量出的宽度会偏几个百分点，导致盒子比字窄、空格被吃掉。

## 2. 排版

### 2.1 三块同一套规则

上文、正文、下文走同一条流水线：同样的分词、同样的单词判定、同样的预留宽度、同样的断行器，只是角色不同，纵向堆叠在同一个坐标系里。原因是它们随时可能互相并入：下文并入后成为正文的结尾，正文并入上文后成为上文的结尾。如果排版规则不同，并入前后同一个字的位置就对不上，动画就无从谈起。

单词按粗体宽度预留盒子，字形在盒内居中。词随时可能被标记加粗，提前留出余量，标记时才不会把后面的词挤开。

### 2.2 断行：整段最优

贪心断行每行只管“尽量多放”，右边缘是被一个个放不下的长词啃出来的。我们改成把整段当作一个优化问题：给每种断法打分，用动态规划选总分最低的。这是 TeX、Safari 的 `text-wrap: pretty` 的共同思路（Chrome 的 `pretty` 只管最后四行，Pretext 本身只做贪心，附带的演示里有 Knuth-Plass 的对比实现）。

核心概念：

- **原子**：断行的最小单位，包括单词、标点、CJK 单字，以及超过一整行的长词被按字素劈开的片段。每个原子带三个信息：宽度、前面能不能换行、后面隔不隔空格。
- **拉伸比 r**：沿用 TeX 的定义。行内缺的（或多出的）宽度，除以这一行所有空格能提供的伸缩量。r = 0 是自然间距，r = 1 是拉到上限。
- **代价**：坏度 `100·|r|³`，一行的代价是 `(linePenalty + 坏度)²`。松紧越极端代价增长越快，所以最优解宁可多折一行，也不留下特别松或特别紧的行。相邻两行松紧反差大也要罚，避免“一行松、一行紧”的呼吸感。
- **有界伸缩**：空格每行可以拉到自然宽度的约 1.3 倍、压到约 0.67 倍，实际拉伸再钳在上限。拉满之后剩下的缺口不继续拉，留作右侧不齐。这保证词间距不会怪异。
- **没有空格可伸缩的行**（CJK、超长词）：缺口按占行宽的比例计代价，和有空格的行用同一把尺子，不会一边代价爆炸一边没事。
- **末行**：不拉伸，空格取自然宽度，只惩罚孤字成行。
- **不连字符**：放不下时不靠断词救场。断词需要词典，且会引入新的失败模式。

参数集中在 `DEFAULT_TUNING`。调参依据是 1000 多个真实英文句子下的统计：非末行平均右侧缺口从约 23px 降到 2 至 4px。若想让右边缘更齐，调大 `maxStretch`，代价是词间距更怪。

### 2.3 一个重要的后果

两端对齐让“同一个词在并入前后不在同一位置”成为常态：正文的末行从自然间距变成中间行，要被拉伸；个别情况下前面的行还会重新断行。所以动画规划不能假设宿主静止（见 3.4）。

## 3. 单词级过渡动画

### 3.1 先把问题抽象清楚

并入下文和并入上文是同一件事的不同角色：一段文字（**移动方**）拼接到另一段文字（**宿主**）的末尾。

- 并入下文：移动方是下文，宿主是正文。
- 并入上文：移动方是正文，宿主是上文。
- 撤销是它们各自的时间倒放。

“独立状态”是两段分开时的排版，“合并状态”是连成一段后的排版。动画就是在这两份排版之间，让每个词从一个位置走到另一个位置。

### 3.2 两个进度量，位姿是纯函数

整个动画只有两个进度量：

- **h**：行内重排进度，0 是独立布局的行内位置，1 是合并布局的行内位置。
- **v**：纵向进度，0 是独立布局所在的行，1 是合并布局所在的行。

每个词的位移和不透明度是 (h, v) 的纯函数（`pieceOffset`、`pieceOpacity`）。方向只决定 h、v 随时间怎么走（`flowPhase`）：

- 并入：h 先从 0 到 1（行内重排），停顿，v 再从 0 到 1（整体上拼）。
- 撤销：v 先从 1 到 0（整体下移分离），停顿，h 再从 1 到 0。

所以追加与撤销共用一套规划和位姿，只有时间轴不同。任何时刻 h 与 v 不会同时在动，所以画面上同一时刻只有一种运动，容易读。

横向段时长随最大行程伸缩，约 `260 + 0.8×最大位移`，限制在 280 至 460ms；停顿 80ms；纵向 160ms。

### 3.3 一行是一条刚性的带子

行内重排时，每一行当作一条带子整体平移。同一行的词共用一个位移，行内相对位置在行程中不变，这样画面像“一行字滑过去”，而不是各词各走各的。

两份布局的行首行尾不同，所以会有词被挤到另一行。规划只看一件事：每个词在两份布局里的**行号差**。

| 行号差 | 含义 | 动画 |
|---|---|---|
| 0 | 留下 | 同一行里平移，位移带符号，可左可右 |
| +1 | 被挤到下一行 | 旧位置向右滑出右界，新位置从左界滑入 |
| −1 | 被提到上一行 | 旧位置向左滑出左界，新位置从右界滑入 |
| 超过 1 | 无法规划 | 放弃，退回通用动画 |

同一行同方向的进出词也共用一个位移，保持刚性，否则它们会在界外叠成一团。进出的两份是同一批字：一份在滑出，另一份在滑入，所以屏幕上始终没有渐入渐出，也没有凭空出现的词。

两份布局的词粒度可能不同（标点可以单独成词元，也可以跟在词后面），所以对齐按“非空白字符的累计偏移”，而不是按词一一对应。

### 3.4 宿主也要规划

规划按“一组词”做。一次动画可以有多组：移动方一组，宿主一组。每组词带自己的纵向行程和前后不透明度：

- 并入下文：宿主（正文）纵向不动，但可能因末行被拉伸而在行内移动。
- 并入上文：宿主（上文）因为顶部多出更早的一句而整体被挤下去，纵向行程为负，横向基本不动。

不透明度也是同一个思路：淡色上下文并入后变成正文色。行内重排只占很小一段，大头留给纵向拼接，所以颜色变化跟着“拼上去”这一步走。

### 3.5 周边元素

- **后续下文**（被并入那一句之后的其余句子）：整体沿同一条纵向路径让位或归位。让位发生在行内重排的最初一小段，因为那时合并布局多出来的那一行还没显形。
- **合并布局多出的行**：这一行的词在后续下文让开之前完全不可见，之后才显形。撤销时反过来，先消失，后续下文再归位。保证两者不会同时出现在同一处。
- **并入上文时顶部多出的那句更早的上文**：随宿主一起沿纵向整体进出。
- **选区底色**：词在两段式移动，CSS 补间跟不上。我们让逐帧动画直接驱动底色：被选中的词每帧在哪，底色就是它们的包围盒，按“组 + 行号”分组。起点和终点分别与动画前后的底色一致，中途词怎么移，底色就怎么长。
- **命中区的悬停底色**：动画期间隐藏并忽略指针，避免一整块底色与逐词移动的文字错位。

### 3.6 为什么用 JS 逐帧，不用 CSS / WAAPI

词级动画需要：同一时刻按词分别计算位置和透明度；各词之间有共享状态（同行共用位移、进出配对）；选区底色要读取每个词的当前位置。这些用关键帧很难表达，用 JS 逐帧算反而是最直接的。实现是一个 `requestAnimationFrame` 驱动的“轨道”列表：每个元素一条轨道，轨道是“时间 → 位移与不透明度”的函数。第 0 帧同步画出，避免元素先以最终状态闪一帧。性能上，一次动画几十到几百个元素、不超过一秒，目前不是瓶颈。

### 3.7 元素复用与 key

动画要靠“同一个词是同一个 DOM 元素”才能补间。`sentenceChange.ts` 判断变化类型（尾部追加、头部前插、两端被删、整句替换），并按字符起点对齐新旧词元，让不变的词保留同一个 key。接缝处的词元（如句末的 `.` 并入后变成 `. `）允许一方是另一方的前缀，否则它会被当成新词，重播入场动画。

只有整句替换（重新取词、粘贴、编辑）才不复用，直接换。

## 4. 设计原则小结

1. **先建模，再画**：每个词的位置是数据，动画是对数据的插值，不靠视觉技巧掩盖。
2. **一个抽象覆盖四种操作**：移动方 / 宿主 / 独立态 / 合并态，h 与 v 两个进度量，并入下文、并入上文、两者的撤销都复用它。
3. **运动要守恒**：每个字都有来源和去向，没有渐入渐出，没有突然出现或消失。滑出的与滑入的是同一批字。
4. **刚性优先**：同一行的词同进同退，进出词共用位移，相互不相交。
5. **规划与渲染分离**：`sentenceFlow.ts` 是纯函数，没有 DOM，所以可以用随机扫描做性质测试（任意时刻同一行上同时可见的词框不重叠，起点逐字吻合旧位置）。
6. **规划不出来就退回**：任何一边文字对不上、或有词要跨过一行以上时，退回通用位移动画，不硬做。

## 5. 已知限制与可改进点

- 没有断词连字符。窄或短的段落里仍有少数行拉满后依然短一截。
- 整段最优让每行的空格宽度不同，并入动画里行内的词会轻微“呼吸”，不是严格刚性。
- 调参只用英文语料统计过，中文没有做统计。
- 动画进行中连续触发新动作时，由新动作接管并取消上一轮，没有做过压力测试。
- 动画只在测试页面里逐帧核对过，没有在真实应用里长期使用过。
